# Wave 2 — post-v0.6.0 plan

Owner directions (2026-07-24): public open-source tool; canvas-first positioning;
SG enforcement **all the way** (backings join the mesh); effort across
observability+M8, service breadth (ALB / CloudWatch Logs / Secrets Manager /
ElastiCache), robustness + secrets hygiene, and RDS-as-TF.

Sequencing rationale: CloudWatch Logs first because it *feeds* the observability
layer wave 1 just built (a log sink the workloads write to, rather than a second
parallel logging story). Drift before more services, because "odin says healthy
while reality diverged" undermines every service we add. SG-end-to-end before
RDS-as-TF, because moving backings onto the mesh changes how RDS is reached.

## W2.1 — CloudWatch Logs (`logs` kind, real backing)

The `logs` node is drawable-only today. Make it real: a gateway model for
`aws_cloudwatch_log_group` + the Logs data plane (`PutLogEvents`,
`GetLogEvents`, `FilterLogEvents`, `DescribeLogStreams`) backed by a real store
(per-env JSON sidecar is enough for v1 — these are dev-scale logs; revisit if
volume demands a real backing container). Wire the substrates to ship their
output there: Lambda RIE stdout → `/aws/lambda/{fn}`, ECS task containers →
`/ecs/{service}`, so `odin logs` and the UI panel read one place regardless of
kind. classify.py gains the `logs` service; hcl.py gains the builder; the CLI's
`odin logs` (wave 1) gains a `--group` path. Integration: a lambda that logs,
then `GetLogEvents` returns its lines.

## W2.2 — Drift detection + reconcile-from-reality

Today tofu-owned resources (vpc/subnet/sg/ec2/ecs/lambda/iam_role/ecr) are
observed by reading odin's own synth JSON, not reality — delete a VM
out-of-band and odin still reports healthy. Fix in two parts:
(a) **detect**: the projection consults reality for TF-owned kinds (a bounded,
cached sweep — `limactl list` / `docker ps` compared against the store) and
marks a resource `crashed` with a verdict when it's gone;
(b) **report, don't auto-heal**: surface drift honestly (World + an event +
`odin world` showing it) and let the user re-Apply — tofu is the authority for
those kinds, so silently re-creating behind its back would fight its state.
Also fix the goaws stranded-port case (a gateway-port change leaves a running
backing unreachable; ensure_backing should recreate rather than adopt).

## W2.3 — Backup / restore (`odin export` / `odin import`)

Losing `.odin/` today orphans containers *and* the startup reaper deletes every
odin VM. Ship `odin export --env <e> > env.tar` (stack lineage + world + keys +
gateway synth stores + tofu state, with a manifest + version) and
`odin import env.tar`, plus a plain-English note in SECURITY.md that the archive
contains credentials. Integration: export, `odin clean --all`, import, Apply →
converges without recreating duplicates.

## W2.4 — Secrets Manager + SSM Parameter Store

Both drawable-only today, and both are the honest answer to "where do secrets
live" (wave 1 only stopped them leaking into echoed responses). Gateway models
+ real per-env store, `aws_secretsmanager_secret`(+version) and
`aws_ssm_parameter` builders, classify entries, and — the point — workloads
fetch them at runtime with their own issued creds, so an IAM edge is what grants
access. This is where odin's IAM story pays off: draw the edge, get the secret;
no edge, real AccessDenied.

## W2.5 — ALB (`alb` kind)

The missing piece for anything production-shaped: `aws_lb` +
`aws_lb_target_group` + `aws_lb_listener`, backed by a real reverse proxy
container (Caddy or nginx, both permissive) per load balancer, whose upstreams
are the target group's registered EC2 VMs / ECS tasks. Health checks map to the
proxy's own. Canvas: an `alb` node in a subnet, edges to the compute it fronts.
Integration: two ECS tasks behind an ALB, curl the LB endpoint, see both
answer; kill one, traffic still served.

## W2.6 — SG enforcement end-to-end (backings on the mesh)

Owner: "go all the way." Today SGs only shape EC2 VM mesh traffic (and only via
the VPC default SG); RDS/goaws/RustFS/dynalite are host containers, so a drawn
`db-sg` is decorative. Make backing containers mesh members: each gets a nebula
cert + joins its env's overlay, its published port bound to the overlay address
rather than a raw host port, and the drawn SG compiles to its firewall. Then
"only the web tier may reach the DB" becomes true. Also finish the EC2 half:
compile the instance's **assigned** SG (not the VPC default) into its VM
firewall. Integration: a VM with an SG allowing 5432 reaches Postgres; one
without it is refused — the promise the canvas has been making all along.

## W2.7 — RDS as a real TF-managed resource

`rds` is the last kind outside Terraform (reconciler-owned), an inconsistency in
the model: `aws_db_instance` isn't emitted, so RDS is invisible to plan/destroy
and to `import-tf`. Build the gateway model (CreateDBInstance / Describe /
Delete / ModifyDBInstance), keep the real Postgres container as its substrate,
and emit the builder. Removes a documented limit and makes teardown uniform.

## W2.8 — ElastiCache (`elasticache` kind)

Entirely absent today, and the standard cache/session tier. Gateway model for
`aws_elasticache_cluster` (redis engine) + a real `redis:7-alpine` container
per node (permissive, tiny), endpoint published as a fact like RDS. Cheap
relative to its value once the pattern from W2.1/W2.7 exists.

## W2.9 — M8: "what's wrong here?" (the agent's real job)

With logs, crash verdicts, drift detection and a log sink in place, the region-
select debugger finally has something to reason over. Cmd+drag a region → "what's
wrong here?" → the agent receives each selected node's desired config, observed
state, verdict, recent events and log tail, and answers in plain English with
per-node suspects. This is the one job the deterministic path genuinely cannot
do, and it's what makes the AI dependency earn its place (see the positioning
decision: the compiler builds, the agent explains).

## Cross-cutting, fold into whichever slice touches them

- Each new kind: catalog entry, HCL builder, classify entry, gateway model,
  substrate, integration test, and an honest ROADMAP limits line. The V1–V5
  pattern is proven — follow it.
- Every new drawable kind must be either backed or explicitly `skipped` at
  apply; never silently ignored (northstar directive 5).
- Public-repo hygiene as we go: CONTRIBUTING.md, issue templates, and a
  first-run experience pass (`odin doctor` is the on-ramp).
